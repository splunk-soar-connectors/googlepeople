## Explicit defaults and metadata differences

- SDK parameter metadata writes `required: false`, `primary: false` and `allow_list: false` explicitly where legacy metadata omitted these keys. These retain the legacy defaults. No mask default changes.
- Asset configuration adds `category: connectivity`, used by the SDK for asset field grouping.
- SDK adds empty contributors and `supports_es_polling: false`. No ingestion or ES polling existed previously.
- Connectivity metadata declares standard status, message and aggregate count datapaths; its legacy output metadata was empty.
- Parameter and action message example values are omitted by SDK serialization. Boolean examples normalize to both true and false. Status examples use `failure` rather than the legacy example `failed`; examples do not define runtime statuses.
- Output declarations and actions are reordered during SDK generation. Datapaths and explicit table column order remain unchanged.
- Custom views use SDK view functions and Jinja templates. The SDK manifest cannot retain legacy custom render title, width and height settings, so platform defaults determine custom widget sizing and title. Headers and content are preserved; verify the presentation on the instance.

## Runtime and packaging changes

- Minimum SOAR version increases from 6.3.0 to the SDK floor 7.0.0.
- Python support changes from 3.9 and 3.13 to 3.13. Python 3.14 is disabled.
- Main module changes from `googlepeople_connector.py` to `src.app:app`.
- SDK connectivity returns its standard success message. SDK action failures add an action-name prefix to preserved legacy error text.
- Third-party dependencies are resolved by `uv.lock` and bundled by the SDK for Linux x86_64 and aarch64. Existing direct Google dependency pins are retained; `requests` is added for the make request action.
- SDK packaging adds `packaged_by`, updates build time and emits empty Python 3.9/3.14 dependency sections. All referenced Python 3.13 wheels are present in the archive.
